# Обращения по персональным данным

Tampermonkey-скрипт для Gmail и Яндекс Почты: выбираете компании, проверяете предпросмотр и нажимаете **«Отправить N писем»**. Скрипт последовательно открывает редакторы, заполняет и отправляет отдельное письмо каждой компании. Доступен режим **«Только черновики»** для ручного добавления подписи или вложений.

Версия **0.2.6** даёт Яндексу обработать ввод адресов перед выходом из поля. Если адрес остался текстом, скрипт повторяет выход из поля без повторного ввода и только при отсутствии других правок. Причина ошибки теперь видна прямо в компактной панели.

Начиная с **0.2.5** скрипт добавляет всех адресатов одной операцией ввода: после последовательного ввода по одному Яндекс мог показывать две карточки адресатов, но сохранять только первого. При едином вводе оба адреса сохраняются после повторного открытия черновика.

Начиная с **0.2.4** скрипт учитывает реальное поведение Яндекса: пока показано предыдущее уведомление «Message sent», повторная отправка не создаёт нового уведомления. Скрипт заполняет следующий редактор, ждёт удаления предыдущего уведомления и только затем нажимает «Отправить». Во время ожидания работает остановка. Подтверждение каждой новой отправки проверяется отдельно.

Начиная с **0.2.2** исправлено заполнение тела: для Яндекса текст передаётся через API CKEditor, после завершения записи редактор получает событие изменения. Перед отправкой сверяются содержимое редактора и его сериализуемый текст. При недоступном API или несовпадении отправка останавливается. Изменение одного лишь HTML больше не считается успешным заполнением.

Скрипт выполняет всю очередь в текущей вкладке почты, без открытия новых вкладок. После запуска панель сворачивается в небольшой блок с прогрессом и кнопкой остановки. Следующее письмо открывается после подтверждения отправки предыдущего. Обновление само ничего не отправляет: запуск происходит только по кнопке в панели. Встроены 27 компаний, 29 адресов и два предоставленных Word-шаблона. Имя скрипта и namespace сохранены для обновления существующей установки.

## Установка и обновление

1. Установите [Tampermonkey](https://www.tampermonkey.net/) в Chrome или Firefox. Разрешите запуск пользовательских скриптов, если браузер требует этого.
2. Откройте установленный скрипт в редакторе Tampermonkey, замените его код содержимым `dist/return-pd-0.2.6.user.js` и сохраните. Для первой установки используйте «Создать новый скрипт». Второй экземпляр при обновлении создавать не нужно.
3. Перезагрузите почту на `mail.google.com` или `mail.yandex.ru` (`.com`, `.by`, `.kz` также включены).
4. Нажмите **«Обращения по ПД · 0.2.6»** справа внизу или команду скрипта в меню Tampermonkey.

`dist/return-pd-0.2.6.user.js` и `dist/return-pd.user.js` идентичны. Обновление сохраняет личную форму и изменения каталога из предыдущей версии.

## Использование

1. Выберите отзыв согласия для рекрутмента или запрос информации об обработке ПД.
2. Выберите действие: **«Отправлять автоматически»** (по умолчанию) либо **«Только черновики»**.
3. Введите ФИО и email для ответа. Дополнительные реквизиты необязательны; форма сохраняется автоматически в этом профиле браузера. В новой вкладке дата обращения — сегодняшняя.
4. Выберите компании. Кнопка с названием открывает реквизиты и предпросмотр. Можно изменить адреса, юридическое наименование, ИНН и ОГРН компании. Для запроса информации предусмотрены сведения о взаимодействии отдельно с каждой компанией.
5. Проверьте получателей, текст и примечания. Подстановки шаблона: `{{ФИО}}`, `{{Компания}}`, `{{Email}}`, `{{Дата}}`. Почтовая шапка из Word не добавляется; письмо начинается с заголовка обращения.
6. Нажмите **«Отправить N писем»**. Дополнительного подтверждения для каждого письма нет. Вся база — 27 отдельных писем в одной вкладке. Оба адреса одной компании находятся в «Кому» одного письма. В режиме черновиков кнопка называется «Подготовить N черновиков»: заполняется один редактор и очередь приостанавливается. Отправьте письмо вручную либо закройте редактор с сохранением черновика, затем откройте панель и нажмите «Продолжить очередь» для следующей компании.

Оставьте эту вкладку почты открытой. Во время работы видны редактор почты и компактный блок с прогрессом, кнопками «Остановить» и «Открыть панель». Одновременно обрабатывается одно письмо. Яндекс использует текущую сессию браузера без чтения аватара и дополнительных действий с профилем. Gmail использует распознанный текущий аккаунт. Во время очереди не переключайте почтовый ящик. Email для ответа в форме не выбирает отправителя.

Автоматически отправляется текст из предпросмотра вместе с распознанной штатной подписью почты, если она настроена. Скрипт не создаёт подписанный документ, не прикрепляет PDF и не устраняет пропуски реквизитов. Примечания и отсутствующие дополнительные поля видны в панели, но не блокируют автоматическую отправку. Если требуется документ или вложение, используйте режим черновиков.

Сбер Мобайл: текст отзыва включает пояснение из Excel; в базе есть инструкция приложить PDF. СКБ Контур: в базе указаны заполнение от руки и подпись. В запрос информации инструкции об отзыве не переносятся. Для запроса предусмотрено предупреждение о подписи документа. Исходные документы не меняются.

## Статусы и остановка

- **В очереди / Открывается** — письмо ожидает обработки или заполняется.
- **Отправляется** — отправка запущена, ожидается результат почты.
- **Отправлено** — после нажатия получено новое явное сообщение почты об отправке и редактор закрылся. Это подтверждение интерфейса почты, не доставки адресату и не удаления ПД.
- **Поля заполнены / Требуется доработка** — результат режима черновиков.
- **Ошибка** — подготовка или запуск отправки не завершились; причина показана в панели.
- **Отправка не подтверждена** — письмо могло уйти, но надёжного подтверждения нет. Проверьте «Отправленные» и текущий редактор. Скрипт не повторяет его автоматически.

**«Остановить»** прерывает дальнейшую работу. Уже нажатую отправку отменить этим нельзя. **«Продолжить очередь»** обрабатывает оставшиеся задания; в режиме черновиков — следующий черновик. При ошибке до открытия редактора разрешён повтор; после начала заполнения повтор требует проверки пользователем. Неопределённая отправка никогда не повторяется этой очередью.

Перезагрузка страницы не возобновляет очередь и не отправляет письма повторно. Старые ссылки заданий версии 0.2.0 при обновлении очищаются без выполнения. Повторный запуск пользователем — новая очередь: те же получатели могут получить ещё одно письмо. Уже открытые или изменённые пользователем черновики скрипт не перезаписывает и не отправляет. Закончите с открытым редактором и закройте его перед продолжением. При неизвестной разметке остаются кнопки копирования адресов, темы и текста.

Статусы из Excel — история исходной базы. Они не описывают текущую очередь и не влияют на выбор компаний. Контакты и особенности взяты из предоставленной базы; актуальность по сайтам компаний отдельно не подтверждена.

## Хранение

Сервера, аналитики, удалённых библиотек и внешних API скрипта нет. Письма передаются обычному интерфейсу выбранной почты, которая сохраняет черновики и выполняет отправку.

- ФИО, email, ИНН, телефон и паспортные поля сохраняются в локальном хранилище Tampermonkey до нажатия «Очистить данные». Данные общие для Gmail и Яндекса в одном профиле браузера; другой браузер или профиль имеет отдельное хранилище.
- Реквизиты и адреса компаний также сохраняются. Дата обращения и режим отправки не сохраняются.
- Шаблоны, сведения о взаимодействии и результаты остаются в памяти исходной вкладки до её закрытия, очистки или истечения 24 часов. Автоматическая очистка не удаляет личную форму и каталог.
- Тексты очереди находятся только в памяти этой страницы. Скрипт не записывает их в хранилище Tampermonkey, не передаёт через URL и не создаёт межвкладочные задания. Разрешение `GM_openInTab` удалено. `unsafeWindow` используется для обращения к API редактора CKEditor в этой же странице; скрипт не читает cookies и не обращается к почтовым API.
- Перед попыткой отправки отдельно записывается отметка по случайному идентификатору, без адресов, текста и личных данных. Неопределённый результат не повторяется автоматически. Отметки удаляются по сроку хранения 24 часа.
- Просроченные отметки и остатки заданий прежних версий очищаются при следующем запуске скрипта; открытые страницы проверяют срок каждую минуту. При закрытом браузере userscript не выполняется и не может удалить данные по таймеру.
- «Очистить данные» удаляет сохранённую личную форму, каталог и временные данные панели. Отметки попыток отправки сохраняются до истечения срока. Уже созданные черновики, отправленные письма и системный буфер обмена эта кнопка не удаляет.

## Разработка и проверки

Требуются Node.js 20+ и Python 3.10+. Python-преобразователь использует стандартную библиотеку.

```sh
npm ci
npm run check
```

`npm run build` читает исходные XLSX/DOCX из корня проекта, обновляет `src/generated/data.json` и собирает userscript. Исходники документов не изменяются; их SHA-256 сохраняется в JSON. Для другого Python можно задать `PD_PYTHON`.

`npm run preview` запускает изолированный предпросмотр на `http://127.0.0.1:4173`, без подключения к почте.

Основные файлы:

- `scripts/convert_sources.py` — преобразование каталога и шаблонов.
- `src/letters.ts` — реквизиты, подстановки и примечания.
- `src/profile-storage.ts` — сохранение личной формы.
- `src/adapters.ts`, `src/yandex-recipients.ts` — заполнение и сверка редактора.
- `src/mail-body.ts` — запись через штатный API редактора и сверка текста; для обычного contenteditable используется команда ввода браузера без прямой подмены HTML.
- `src/send-letter.ts` — нажатие отправки и ожидание подтверждения.
- `src/queue.ts`, `src/transport.ts` — последовательная работа в текущей вкладке, отмена и защита от повторов.
- `src/ui.ts`, `src/ui-surface.ts`, `src/launcher.ts` — панель в изолированном iframe и отдельная восстанавливаемая кнопка запуска.

Автотесты покрывают базу 27/29, оба шаблона, длинную кириллицу, реквизиты и особые случаи, форму и сохранение, очереди до 50 писем, остановку, отсутствие автоматического повтора, TTL, обе DOM-модели почты и раздельные сценарии отправки и черновиков. Сборка проверяется на последовательную отправку в одном документе и отсутствие открытия вкладок. Подтверждение отправки проверяется отдельно от нажатия кнопки; старые уведомления и одно лишь исчезновение редактора не считаются успехом.

Регрессия 0.2.4 воспроизводит подтверждённое в живом Яндексе поведение: при видимом старом уведомлении второе письмо уходит, но нового уведомления не появляется. До исправления очередь останавливалась после второй отправки. Исправленный сценарий проверяет 27 последовательных отправок с отдельным подтверждением каждой, сохранённые тексты, получателей, отсутствие новых вкладок и повторов.

Живая проверка 15 сентября 2026 года в Яндекс Почте в Chrome:

- В повторном пользовательском запуске версии 0.2.5 после 10 отправок адрес «Магнита» остался обычным текстом; панель сообщила об отсутствии подтверждённого получателя. Повторный вход в поле «Кому» и выход из него, без изменения адреса, создали карточку получателя. Версия 0.2.6 обрабатывает этот сценарий автоматически. Эта диагностика не запускала отправку повторно.
- В установленной версии 0.2.6 создан черновик «Магнита»: получатель, тема и все четыре пункта заполнены скриптом. После сохранения и полной перезагрузки страницы черновик открыт заново; адрес, тема, компания, пункты и дата сохранены. Заполненное письмо оставлено в «Черновиках», отправка не запускалась.
- Версия 0.2.4 отправила все 21 оставшееся обращение одной очередью примерно за 104 секунды. Счётчик дошёл до «Отправлено 21 из 21». Число писем в «Отправленных» выросло с 14 до 35; у всех 21 новых писем есть текст обращения. Дополнительно открыты полные тексты и проверены пункты, дата и компания. Уже отправленные обращения исключались из запуска.
- Обнаружено, что прежний ввод получателей по одному показывал две карточки, но Яндекс сохранял только первого адресата. В версии 0.2.5 скрипт создал черновик «Купера» одним вводом двух адресов. После штатного сохранения, полной перезагрузки почты и открытия из «Черновиков» восстановились оба адреса и полный текст из 1442 символов. Проверочный черновик удалён в корзину.
- Версия 0.2.5 дослала обращения только двум пропущенным дополнительным адресатам «Купера» и «Золотого Яблока». Очередь завершилась «Отправлено 2 из 2», а число отправленных писем выросло до 37. Оба письма открыты из «Отправленных»: подтверждены адресаты, компания, все четыре пункта и дата; длина текста — 1442 и 1451 символ соответственно. Полные списки адресов в каталоге восстановлены.
- Финальный `npm run check` версии 0.2.6: проверка типов и 268 успешных тестов, включая очередь 27 писем с 29 сохранёнными получателями, подавление повторного уведомления Яндексом, задержанный ввод получателя, проигнорированный первый выход из поля, остановку и сохранение пользовательских правок.

Gmail, Firefox и полные очереди на 27/50 компаний проверены моделями, не живыми рассылками. Наличие письма в «Отправленных» не подтверждает доставку или удаление ПД компанией. Варианты интерфейса с неподдержанными элементами или iframe-редакторами могут потребовать доработки адаптера.

Создание PDF, подпись документов, автоматическое прикрепление файлов и обработка ответов компаний не реализованы.
